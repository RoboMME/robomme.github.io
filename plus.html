What is RoboMME-Plus?

RoboMME-Plus asks two questions about robot memory: (1) do the skills that policies learn on RoboMME transfer when task conditions change, and (2) how much new experience does a policy need to adapt? It keeps RoboMME’s 16 tasks across Counting, Permanence, Reference, and Imitation, and makes them harder with more objects and repetitions, continuous motion, occlusion, and limited correction. To test how well methods generalize, its 800 held-out test episodes add perceptual and mechanism variations that are mostly unseen in training.

Adaptation experience is budgeted. A policy may use the 50 released offline demonstrations, up to 10 simulator rollouts per task, or both. The same settings apply to fine-tuned policies and agentic methods. Every method is frozen before testing, and results are reported by setting.

A Small Training Set for Adaptation

We keep the training set small to study adaptation efficiency: how well models adapt their existing memory skills from a few demonstrations and a capped interaction budget.

Offline demonstrations. The training split contains 50 successful episodes, previewed in the videos above: three per task, and five for MoveCube. Each episode includes front and wrist RGB-D images, camera calibration, robot states, actions in every action space, task goals, subgoal annotations, and episode information. Use them for training or as in-context examples.

Simulator interaction. Policies may also run the RoboMME-Plus simulator on the provided training seeds, within the rollout budget: a rollout is one episode from one training seed, and each task allows at most 10. Training and test seeds are disjoint within each task; use test seeds only for evaluation.

Pick one setting before development. The rollout limit is shared across all training seeds of a task.

Rules

  1. Count rollouts. Every RoboMME-Plus simulator start counts, including previews, failed setups, retries, demonstration replays, debugging, verification, and model selection. Stay within the per-task budget and the episode step limits. Agentic development follows the agentic development guide: log every agent session and simulator start, and include the development audit.
  2. Use only permitted resources. Use only the data, training seeds and documents your setting allows. Keep task and simulator code, test data, test results and other methods’ solutions away from development, and do not hand-write solutions from task details. The original RoboMME dataset and simulator may be used freely.
  3. Submit the final code. The RoboMME team re-runs it on all 800 test episodes, and the leaderboard uses that run. Keep the policy unchanged during testing and clear its memory between test episodes. If evaluation calls a closed API or gated model, email robomme2026@gmail.com with the pull-request link and prepare an API key with enough quota for 800 test episodes per submitted setting.
  4. Report resource usage. Report the setting, the demonstrations used, the rollout budget, the rollouts actually used per task, and estimated development and evaluation API costs in USD; a reasonable estimate is enough. Compare methods only under the same setting and budget.

Evaluation and Leaderboard Submission

After development, evaluate the frozen system on the 800 held-out test episodes (50 per task) with the robomme_plus package, using the joint_angle, ee_pose, or waypoint action space, with the default variations and step limits. Only status == "success" counts; failures, timeouts and errors stay in the denominator. Report results under changed test conditions separately.

Minimal evaluation loop 
from robomme_plus import BenchmarkEnvBuilder

builder = BenchmarkEnvBuilder(
    "VideoRepick", dataset="test", action_space="joint_angle"
)
env = builder.make_env_for_episode(0)
try:
    obs, info = env.reset()
    task_goal = info["task_goal"][0]
    while True:
        action = policy.predict(obs, task_goal,
                                error_message=info.get("error_message"))
        obs, reward, terminated, truncated, info = env.step(action)
        if terminated or truncated:
            success = info.get("status") == "success"
            break
finally:
    env.close()

Implement policy.predict for your model. Keep the demonstration frames returned by reset. Observation fields are lists; the last item is the current observation.

Leaderboard submission

The leaderboard has two tracks, and both follow this protocol: Non-Agentic, for robot policies trained or fine-tuned for control, such as VLAs; and Agentic, for systems that prompt pretrained foundation models, open or proprietary, to plan, act, or write code.

The leaderboard ranks results within each setting, at 10 rollouts per task for Interaction-only and Hybrid; results with other rollout budgets can be reported optionally.

Submit with the submission template: per-task results plus the usage listed in the rules above, in a pull request.
